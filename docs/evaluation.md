# Оценка качества маршрутизации

AI Process Pilot использует **детерминированный rules-based классификатор**, а не обученную модель. Поэтому качество контролируется не «на глаз», а на отдельном размеченном regression-наборе.

## Набор

Файл: `tests/fixtures/evaluation.jsonl`.

Каждая строка содержит:

```json
{"text":"Ошибка 500 при входе","category":"technical","priority":"medium"}
```

В набор входят платежи, технические обращения, продажи, доставка, общие запросы, срочность, юридическая эскалация и неоднозначные формулировки.

Это **не репрезентативная выборка реального бизнеса** и не основание заявлять production-accuracy. Набор нужен для обнаружения регрессий: изменение правил не должно незаметно ухудшать уже проверенные сценарии.

## Запуск

```bash
processpilot-eval tests/fixtures/evaluation.jsonl
```

или:

```bash
python -m processpilot.evaluation tests/fixtures/evaluation.jsonl   --min-category-accuracy 0.90   --min-priority-accuracy 0.90
```

Команда печатает количество примеров и accuracy отдельно для категории и приоритета. Если результат ниже порога, процесс завершается с ненулевым exit code.

## CI gate

GitHub Actions запускает evaluation на Python 3.11–3.13. Это означает, что изменение классификатора, которое ломает размеченные сценарии, делает CI красным.

## Как развивать дальше

Для реального пилота рекомендуется:

1. собрать 100–500 обезличенных обращений;
2. разметить их минимум двумя людьми;
3. разделить development и holdout выборки;
4. считать confusion matrix, precision/recall/F1 по классам;
5. отдельно считать recall для high-priority обращений;
6. фиксировать стоимость false negative / false positive;
7. пересматривать правила только после анализа ошибок.

Такой подход позволяет сравнивать rules-based, LLM и гибридные маршрутизаторы на одинаковой выборке.
